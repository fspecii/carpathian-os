# Carpatic motion: boot splash, greeter, login intro, screensaver

One story: **mountains rise in layers, the ember sun comes up behind them, then the sun breathes.** Inspired by what Omarchy does at startup (Plymouth progress bar, a
terminaltexteffects greeter, per-theme intro videos, a ttfx screensaver, direct boot), all rebuilt from scratch in the Carpatic design language
(`docs/DESIGN-SYSTEM.md` section 7.1). What Omarchy does and what was kept or changed: `RESEARCH.md`. Other owners' to-do list: `NEEDS.md`. Fast boot: `FASTBOOT.md`.

## Boot splash (Plymouth)
Three parallax ridge layers rise (far first, 600 ms each, 120 ms apart), the logo peaks rise in layers, the sun comes up behind the main peak with one gentle overshoot, the
wordmark fades in, a wide halo warms up and a small core glow **breathes** (4 s period). Under the wordmark a progress bar runs: *fake then real, but honest*: the fake part is
`0.9 * t / (t + 5)` (fast, then ever slower, never reaches 0.9, never stops), the real part is plymouth's boot progress; the bar shows the larger of the two, approached
smoothly, and **never decreases**; a shimmer keeps sliding on the filled part so it never looks stuck. When the passphrase is asked the logo moves up and the dialog fades in
on the same scene; after an answer the bar comes back where it was.
* **Layout** is computed from the window size and again whenever the size changes (display hot-plug, like Omarchy's `refresh_callback`); logo, ridges and dialog scale with the height. Rendered and checked: 640x400, 800x600, 1024x768, 1280x1024, 1600x1200 (`docs/screenshots/motion-plymouth-resolutions.png`). Wide, portrait and 4K layouts follow the same formulas but were NOT rendered (the BIOS lab only has VBE modes up to 1600x1200).
* **Time base**: wall clock from the boot-progress callback's `duration` (it advances every frame), not a frame counter, so a slow machine does not stretch the entrance (Omarchy counts frames at an assumed 50 fps).
* **Frame rate, measured** (`tests/plymouth-frames.sh` with `CARPATIC_FPSPROBE=1`, a white marker moving 1 px per script frame, QEMU/KVM 1024x768, host load average 5): **50 fps steady** (plymouth's script plugin refreshes at 50 Hz: that is the ceiling, NOT 60), **31 to 45 fps during the 1.45 s entrance** (the original theme measured 34 fps there). The big halo is a costly blend, so it changes in 6 steps and only the small core breathes (every 3rd frame); that took the steady state from 43 to 50 fps.
* **Reduced motion**: kernel line `carpatic.reduced-motion` (persist with `carpatic-boot motion reduced`). The script cannot read the command line, so `initfs-splash.sh` copies the 2 px wide `mflag-reduced.png` over `mflag.png` and the script reads that image's width. Everything then fades in within 120 ms, nothing rises or breathes, the bar fills without easing (`docs/screenshots/motion-plymouth-reduced.png`).
* **Unchanged**: `quiet splash plymouth.ignore-udev`, `carpatic.splash=off|sim-black`, the screen/keyboard checks and every text-prompt fallback of `initfs-splash.sh`. Lab: 17 BIOS checks pass (`design/plymouth/tests/lab-test.sh`, images built without sudo by `tests/lab-images-nosudo.sh`); the UEFI scenarios need sudo and were NOT run (see NEEDS.md).

## Installer greeter
The ASCII mountain logo of the wizard rises row by row from the base line (1.8 s), the ember sun comes last, then a bright band drifts over the peaks in a seamless 4 s loop until
Return. Only the 16 indexed ANSI colours are used (the Linux console crushes truecolour; the console palette comes from the design tokens). 30 fps, **no process forked per
frame** (frames are generated by awk once, timing is a `read -t` on a silent pipe), terminal re-measured on SIGWINCH and once a second (a VT can grow after boot), `stty sane`,
attributes reset and cursor shown on any exit including SIGTERM. `CARPATIC_NO_ANIM=1`, `MOTION=reduced` or `TERM=dumb`: one static screen. terminaltexteffects is pure Python
and would run on musl, but it needs python and pip on the live ISO; not used (pip was not available on the host to test the wheel, so this is untested).
Measured: about 4 percent of one core steady (30 fps, 100x30). `carpatic-greeter-anim --dump DIR` writes every frame for tests and previews.

## Login intro
Three tinted ridge layers rise over the dark, the ember glow warms up, the ridges sink, and an **iris opens from the sun onto the live desktop** (an X shape mask, so no compositor
is needed). 1.55 s in total (hard stop 2.5 s), any key or click skips at once. `carpatic-intro auto --wait` is the first thing the session autostart runs; the first frame is the
colour `xsetroot` just set, so there is never a flash; the wallpaper loads *under* the cover; the iris waits for the root pixmap (feh) so the reveal never shows an unstyled root.
* **Native C player** (`src/`, plain Xlib + MIT-SHM + XShape, no GTK/cairo/python): starts in a few milliseconds, override-redirect window, takes no focus and no grab (keys and buttons are polled, keys held from the login are ignored), repaints only what changed (23 percent of the pixels), draws the colours of the active theme (accent, orange; `settings.conf` ACCENT wins). An earlier Python/GTK version needed 1.5 s just to start in the VM and stalled for 0.2 to 0.5 s; it was replaced.
* **Measured in the QEMU guest (software X, 1280x800)**: mean frame 16.7 ms, p95 16.8 to 19.3 ms, max 17 to 31 ms, 0 to 2 of 93 frames over 25 ms, CPU 0.47 to 0.6 s per play, 1.58 to 1.61 s. This is 60 fps in the VM; **real hardware with a GPU was not tried**.
* **Net time to desktop**, same VM, `desktop/session/autostart.sh` with timestamps, two cold boots each: without the intro the wallpaper is set 0.16 s after the autostart begins (`carpatic-intro auto` costs 30 ms to say "off"). With the intro the rest of the autostart is **held back by only 0.13 s** (the call returns when the first frame is up) and the intro starts 0.09 s after the autostart begins. **But the desktop becomes visible 1.5 s later** (it is covered for 1.6 s). The 300 ms target is met for loading, not for visibility: any animation you can see costs its own length. That is why the default is `first-login-only`, and why every key skips it. On the first login the Welcome wizard loads underneath.
* **Self-skips**: setting `off`, reduced motion, battery saver, battery under 20 percent, already played (this login, or ever in first-login-only), no display, and a screen that cannot keep up: the player measures its own first frames (median over 45 ms, or any stall over 350 ms) jumps to the reveal and writes `intro.slow`, so later logins skip it until `carpatic-intro reset`. A late start (more than 1.2 s after the session began) plays the short version (iris at 0.75 s).
* Optional per-theme video like Omarchy: `<theme>/intros/<wallpaper name>.mp4|m4v|mov|webm|mkv` is played with `mpv` or `ffplay` when installed (`carpatic-intro video` prints the match). No video is shipped.
* CLI: `carpatic intro play | set first-login-only|every-login|off | status | reset`. Settings: *Startup and screensaver*.

## Screensaver
A fullscreen `st` (under dwm, fullscreen through `_NET_WM_STATE`) runs `saver.awk`: **brand** (the mark with a spruce-to-ember colour wave), **rain** (mountain glyphs fall and leave a spruce trail), **sunrise** (sky gradient, three ridges, the sun rising behind them), **stars** (a starfield flying past, an ember star now and then). Any key or mouse movement ends it (mouse reporting is switched on in the terminal, plus an `xprintidle` check for input that did not reach the window), the cursor is hidden, the tty is restored on any exit.
* **Idle wiring**: `carpatic-screensaver watch` (autostart) polls `xprintidle`; it starts after the chosen minutes (default 3), always at least one minute before `carpatic-idle`'s xautolock lock (10 minutes, `CARPATIC_IDLE_MIN`). The locker is untouched; the screensaver ends itself when `slock` / `carpatic-lock-screen` appears, so the lock screen is never hidden behind it. It does not start on battery (switch in Settings), in power-saver, with reduced motion, while a window is fullscreen, or when turned off.
* **Always a night scene**: light themes keep their (lightened) accent but get the dark background.
* **CPU, measured** (200x56 cells, 20 fps, bash plus awk, steady state, host load average 4): brand 3.4, sunrise 3.0, rain 6.2, stars 7.4 percent of one core with **mawk** (an earlier run that showed 1 to 2 percent missed the awk process and is withdrawn). Alpine's default busybox awk is 10 to 30 times slower on these frame generators (400 frames cost 3.1 s brand, 7.6 s rain, 4.0 s sunrise, 7.0 s stars), so the launcher prefers mawk and halves the frame rate on busybox; the package must depend on `mawk` and `xprintidle`.
* Verified on the real guest screen under dwm (`docs/screenshots/motion-screensaver-vm.png`); the idle watcher started it by itself in the session while the VM sat idle.
* CLI: `carpatic screensaver start [effect] | stop | status | set on|off | timeout N | effect NAME | battery yes|no`.

## Fast boot
See `FASTBOOT.md`: Limine `timeout: 0` for a single-OS install (about 2.4 s saved in the UEFI lab), never with another OS; `carpatic-boot menu hide|show`. The "hold a key to show the menu" behaviour is not verified.

## Tests (`tests/`)
`run-all.sh` (host only, a few minutes, no VM slot, no sudo): `test-greeter.sh` (15), `test-screensaver.sh` (35, includes Alpine's own busybox awk from the lab rootfs), `test-intro.sh` (23), `test-boot.sh` (20), `test-pages.py` (13).
`run-all.sh --lab` adds `test-plymouth.sh` (BIOS lab scenarios, reduced motion, frame-rate probe, host mount check before/after). Lab tools: `plymouth-frames.sh` (boots the real theme and the real `initfs-splash.sh`, records frames through the QEMU monitor), `fastboot-lab.py`, `lab-images-nosudo.sh`, `src/intro-host --selftest` (incremental drawing equals full redraw on every frame). VM-only checks (run by hand in a clone of golden-desktop2, `VM_RAM=2048`): intro frame log `~/.local/state/carpatic/intro.log.json`, screensaver fullscreen under dwm.
Tools: `tools/vt2png.py` (terminal emulator to PNG, pycairo), `contact_sheet.py`, `mkgif.py` (pure Python GIF), `frames-analyze.py`, `fps-probe.py`.

## Install
`sh motion/install.sh [--root DIR]` (builds the player with `make -C src`; needs `gcc libx11-dev libxext-dev`). The apk package is the packaging agent's (NEEDS.md).
